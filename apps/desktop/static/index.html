模型与 Provider

会话型 Provider (Codex)

复用本地授权驱动，无需手动填写密钥。

Codex Provider 说明

这里控制 `codex-default` 背后实际使用的上游模型，以及额外暴露给第三方客户端的模型别名；不会影响你已经导入的账号数据。

可同时暴露多个 Codex 模型别名给第三方客户端，例如 `codex-5.4`、`codex-5.4-mini`、`codex-5.1-max`、`codex-5.1-mini`。
OpenAI-Compatible

扩展 Provider，可选接入标准 OpenAI 兼容云端接口。

OpenAI-Compatible Provider 说明

这是额外的标准兼容 Provider，可与 Codex 同时存在；适合接入你自有的云端中转、官方 API 或其他 OpenAI 兼容服务。若当前只围绕 Codex 使用，可保持关闭状态。

本地模型 (Ollama)

Ollama Provider 说明

策略路由

决定哪类第三方请求该走默认模型、活动账号、固定账号，还是命中动态号池。

默认路由

当没有命中任何策略规则时，网关会从这里决定最终回退模型。

默认模型的作用

当第三方客户端没有显式指定模型，或策略路由未改写目标模型时，网关会把请求导向这里设置的默认模型别名。这里决定的是“默认去哪里”，不影响 Provider 自身配置。

规则命中

按客户端标签或请求模型匹配规则，把请求分流到不同目标。

策略路由使用说明
  • 一条规则 = 至少 1 个匹配条件 + 至少 1 个目标字段，可按客户端或模型把流量分配到不同模型、不同账号。
  • 目标账号模式选择“沿用当前活动账号”时，命中规则后仍由账号页当前活动账号决定最终额度来源，适合你灵活切号。
  • 目标账号模式选择“固定账号”时，命中规则的请求会固定走指定账号，适合给某个客户端预留专用额度。
  • 目标账号模式选择“号池调度”时，命中规则的请求会转入左侧“号池调度”页定义的动态号池，再由池内策略自动选号。
  • 多条规则按优先级生效，数字越小越先命中；只要命中第一条启用规则，就不会继续往下匹配。

号池与路由

把多个桌面端 Codex 账号编成动态号池，并与策略路由一起控制共享请求命中哪里。

号池调度开关
关闭后，所有“号池调度”目标模式都会退化为普通路由，不会再自动切号。
号池与策略路由的关系

策略路由负责“把哪类请求导向哪个目标”；号池调度负责“目标号池内部如何选账号、何时跳过、何时切下一个”。如果你仍想手动切号，请继续使用“沿用当前活动账号”模式。

动态号池
定义池成员和自动切号策略；兼容策略路由配置会在后续切片并入本页 Tab。
推荐使用方式

例如给 OpenClaw 配置一条 `clientTag=openclaw + model=codex-default -> 号池 A` 的策略路由，然后在号池 A 中放入多个桌面端 Codex 账号。网关会在每次请求开始前自动挑选一个满足阈值的账号；若本次请求命中的账号出现额度耗尽、鉴权失效或短期限流，会按池内策略尝试下一个候选账号。
