# 打包与发布说明

本文档描述 `Local AI Gateway` 当前的桌面打包与发布脚手架。

## 1. 当前目标

当前阶段的打包能力定位为：

- 先具备本地构建桌面包的基础能力
- 为后续发布流程预留统一脚手架
- 暂不追求完善的签名、公证与自动发布

当前已验证：

- `npm run package:desktop` 可生成目录包
- 产物位置为 `release/mac-arm64/Local AI Gateway.app`
- `npm run smoke:desktop-package` 可自动执行目录包构建并校验 `.app / Info.plist / app.asar` 是否齐全

## 2. 现有脚本

### 2.1 构建目录包

```bash
npm run package:desktop
```

该命令会：

1. 先执行 `npm run build`
2. 再通过 `electron-builder --dir` 生成目录形态的桌面包

补充说明：

- 该命令保留正常的 Electron Builder 默认行为
- 如果本机存在可用签名证书，可能会进入签名流程
- 适合真正准备产出目录包时使用

### 2.2 构建可分发包

```bash
npm run dist:desktop
```

该命令会：

1. 先执行 `npm run build`
2. 再通过 `electron-builder` 生成 macOS 可分发产物

### 2.3 发布前自动验收

```bash
npm run preflight:release
```

该命令会顺序执行：

1. `npm run build`
2. `npm test`
3. `npm run smoke:gateway`
4. `npm run smoke:desktop-package`

适合在准备打包或提交发布物前做一次完整预检。

补充说明：

- `smoke:desktop-package` 会关闭真实开发证书自动发现，优先走不依赖本机证书权限的目录包验收
- 它的目标是验证桌面包能否成功产出，以及 `.app / Info.plist / app.asar` 是否齐全
- 在 macOS 上它通常会退到 `ad-hoc signature`，但不会替代最终的正式签名 / 公证发布流程
- 它的意义是避免预检阶段被真实证书签名、公证或本机权限问题拖住

- [electron-builder.yml](/Users/henery/code/local-ai-gateway/electron-builder.yml)

- 产品名：`Local AI Gateway`

当前实际状态：

```bash

npm test

```
