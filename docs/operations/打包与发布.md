# 打包与发布说明

本文档描述 `Local AI Gateway` 当前的桌面打包与发布脚手架。

## 1. 当前目标

当前阶段的打包能力定位为：

- 先具备本地构建桌面包的基础能力
- 为后续发布流程预留统一脚手架
- 暂不追求完善的签名、公证与自动发布

当前已验证：

- `npm run package:desktop` 可生成目录包
- 产物位置为 `release/mac-arm64/Local AI Gateway.app`
- `npm run generate:icons` 可基于 `apps/desktop/assets/icons/source/` 中的 SVG 资源自动生成 `.icns`、Dock 图标与状态栏图标
- 当前 App / Dock 图标会保留透明留白以适配 macOS 原生圆角图标观感，状态栏图标则使用真正透明背景的语义图标样式
- 状态栏 `Active` 图标会生成多帧 PNG，并在运行时轮播显示环绕动效
- `npm run smoke:desktop-package` 可自动执行目录包构建并校验 `.app / Info.plist / app.asar` 是否齐全
- `npm run smoke:desktop-package` 现会额外校验安装包内关键运行时依赖是否随包分发，避免“开发态可运行、安装后缺包崩溃”
- `npm run smoke:desktop-package` 现会额外校验应用图标、Dock 图标与状态栏图标是否真正进入安装包
- 桌面打包脚本现会在构建完成后自动把 `better-sqlite3` 恢复到当前 Node 运行时 ABI，避免打包后本地测试链路被 Electron ABI 污染
- `npm run release:manifest` 可为当前 `release/` 目录生成发布物清单与校验信息
- `npm run dist:desktop:ready` 已实测成功产出 `zip / dmg / blockmap / latest-mac.yml`，并会在构建完成后自动刷新 `release-manifest.json`

## 2. 现有脚本

### 2.1 构建目录包

```bash
npm run package:desktop
```

该命令会：

1. 先执行 `npm run build`
2. 再执行 `npm run generate:icons`
3. 再通过 `electron-builder --dir` 生成目录形态的桌面包

补充说明：

- 该命令保留正常的 Electron Builder 默认行为
- 如果本机存在可用签名证书，可能会进入签名流程
- 适合真正准备产出目录包时使用

### 2.2 构建可分发包

```bash
npm run dist:desktop
```

该命令会：

1. 先执行 `npm run build`
2. 再执行 `npm run generate:icons`
3. 再通过 `electron-builder` 生成 macOS 可分发产物

### 2.3 仅生成图标资源

```bash
npm run generate:icons
```

该命令会：

1. 读取 `apps/desktop/assets/icons/source/` 下的 SVG 源文件
2. 生成 `app-icon.icns`
3. 生成 Dock / 窗口使用的 `app-icon.png`
4. 生成状态栏使用的 `tray-idle / tray-active / tray-error` PNG 资源

当前实现说明：

- SVG 转 PNG 由 `@resvg/resvg-js` 完成，避免 macOS `qlmanage` 在某些场景下把透明背景错误转成白底
- App / Dock 图标采用“透明外边距 + macOS 风格圆角底板”的做法，既保持原生程序坞观感，也避免出现尖角方形边缘
- 状态栏图标采用真正透明背景，只保留三层矩形与状态语义元素，确保在浅色与深色菜单栏中都能自然贴合
- 安装版托管网关会通过应用自身可执行文件的 Node 模式拉起，避免打包后把工作目录误指向 `app.asar` 文件本身而触发 `spawn ENOTDIR`

当前图标源文件约定：

- `apps/desktop/assets/icons/source/app-icon.svg`：主应用图标
- `apps/desktop/assets/icons/source/brand-icon.svg`：桌面端左侧栏品牌图标
- `apps/desktop/assets/icons/source/tray-*.svg`：状态栏图标

### 2.4 发布前自动验收

```bash
npm run preflight:release
```

该命令会顺序执行：

1. `npm run build`
2. `npm test`
3. `npm run smoke:gateway`
4. `npm run smoke:desktop-package`

适合在准备打包或提交发布物前做一次完整预检。

### 2.5 生成发布物清单

```bash
npm run release:manifest
```

该命令会扫描当前 `release/` 目录，并生成：

- `release/release-manifest.json`

当前清单会记录：

- `.app` 目录包的文件数量与总体积
- 其他发布物文件的相对路径、大小与 `sha256`
- 清单生成时间

适合在你完成目录包、`zip` 或 `dmg` 构建后，做一次本地留档与版本核对。

### 2.6 一键生成可核对发布物

```bash
npm run package:desktop:ready
```

或：

```bash
npm run dist:desktop:ready
```

它们会在通过预检后，继续构建桌面产物并自动生成 `release-manifest.json`。

补充说明：

- `smoke:desktop-package` 会关闭真实开发证书自动发现，优先走不依赖本机证书权限的目录包验收
- 它的目标是验证桌面包能否成功产出，以及 `.app / Info.plist / app.asar` 是否齐全
- 它还会验证 `pi-ai / fastify / better-sqlite3` 等关键运行时依赖是否正确进入安装包
- 构建结束后会自动执行一次 `npm rebuild better-sqlite3`，恢复当前开发环境的 Node ABI
- 在 macOS 上它通常会退到 `ad-hoc signature`，但不会替代最终的正式签名 / 公证发布流程
- 它的意义是避免预检阶段被真实证书签名、公证或本机权限问题拖住
