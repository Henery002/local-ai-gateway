# 开发与变更流程

本文档用于约束本项目的日常开发、调试与回溯流程。

## 1. 基本原则

- 功能改动优先保持 gateway 主链路稳定
- 先保证服务可独立运行，再考虑控制面体验增强
- 不在仓库中保存任何敏感 token、refresh token 或 cookie
- 所有项目内 Markdown 文档统一使用中文

## 2. 变更记录要求

每一次改动都必须同步更新根目录的 [CHANGELOG.md](/local-ai-gateway/CHANGELOG.md)。

适用范围包括：

- 新需求
- 功能新增
- 配置调整
- 代码重构
- bug 修复
- 调试过程中得到的重要结论
- 接口变更
- 文档补充或修订

## 3. CHANGELOG 维护规范

维护要求：

- 按日期降序排列
- 同一天收敛到同一时间戳条目下
- 使用精简短句，避免大段叙述
- 只记录后期回溯真正有价值的信息
- Git 提交信息统一使用中文
- 影响 workspace 包解析的改动，应确保测试直接使用源码别名而不是依赖旧 `dist` 产物

推荐分类：

- `新增`
- `调整`
- `修复`

## 4. 推荐开发流程

1. 阅读相关 PRD、架构文档与现有实现。
2. 在本地完成开发、构建与测试。
3. 对关键路径做最小 smoke 验证。
4. 更新相关文档。
5. 更新 `CHANGELOG.md`。
6. 如涉及概念边界、产品理解或长期开发清单，更新《项目答疑与开发清单》和《概念地图》。

## 5. 验证要求

至少应覆盖：

- `npm run build`
- `npm test`
- `npm run smoke:gateway`

如改动涉及网关主链路，建议额外验证：

- `GET /healthz`
- `GET /v1/models`
- `POST /v1/chat/completions`
- 如涉及工具调用，则验证工具调用返回
- 如涉及流式逻辑，则验证 SSE

## 6. 文档更新建议

以下场景建议同步更新文档：

- 产品范围变化：更新 `docs/prd/`
- 模块结构变化：更新 `docs/architecture/`
- 运行方式变化：更新 `docs/operations/`
- 概念语义变化：更新 `docs/architecture/概念地图.md`
- 重要答疑与后续开发项变化：更新 `docs/operations/项目答疑与开发清单.md`
- 长期规则变化：更新 `AGENTS.md`
