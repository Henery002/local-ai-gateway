# 网关常驻服务与运维日志

> 适用范围：公网共享试运行、Cloudflare Tunnel 联调、本机安装版长期运行。

## 1. 当前结论

- Cloudflare Tunnel 由 `com.local-ai-gateway.cloudflared` 常驻。
- 本地网关服务由 `com.local-ai-gateway.gateway` 常驻。
- 两个服务都使用当前用户的 macOS LaunchAgent，不需要 root 权限，不写入系统级守护目录。
- 业务数据仍保存在 `~/Library/Application Support/local-ai-gateway/`，常驻服务、开发环境重启、重新打包或覆盖安装都不应删除成员、Key、号池、用量、告警和配置。

## 2. 网关常驻服务

网关 LaunchAgent 文件：

```text
~/Library/LaunchAgents/com.local-ai-gateway.gateway.plist
```

持久化 launcher：

```text
~/Library/Application Support/local-ai-gateway/service/gateway-launcher.mjs
```

安装版会额外生成 service runner：

```text
~/Library/Application Support/local-ai-gateway/service/gateway-service-runner.mjs
```

常驻服务日志：

```text
~/Library/Application Support/local-ai-gateway/logs/gateway-service.out.log
~/Library/Application Support/local-ai-gateway/logs/gateway-service.err.log
```

服务特性：

- `RunAtLoad=true`：登录后自动启动。
- `KeepAlive=true`：异常退出后由 launchd 拉起。
- 安装版使用当前 `.app` 自带 Electron runtime 的 Node 模式运行打包内 `server.js`，不依赖系统 Node 或开发仓库 `node_modules`。
- 启动前检查网关端口，若旧的本项目网关进程仍在监听，会先定向停止旧进程；从桌面端点击“启动服务”时，也会先停止同进程内临时网关，避免重复监听。
- 运维页执行启动或重启时，会把当前 LaunchAgent PID 视为本网关进程；若 `bootout` 后端口短暂未释放，会等待旧 PID 退出后再启动，避免把刚退出的常驻服务误判为外部进程。
- 安装版冷启动可能需要加载账号快照、数据库和打包内原生模块，桌面端会等待网关健康检查最多 45 秒；期间若端口最终变健康，不应再显示启动失败。
- 若端口被非本项目进程占用，不会强杀，会在运维页提示端口占用。
- 如果服务暂时启动失败，桌面控制台仍应能打开，以便进入“运维与日志”查看 `gateway-service.err.log` 并执行重启服务。

## 3. 运维与日志页面

桌面端左侧“运维与日志”用于集中处理运行维护：

- 查看网关 LaunchAgent 状态、PID、端口和当前端口进程。
- 查看 Cloudflare Tunnel LaunchAgent 状态、PID、Tunnel 名称和 Hostname。
- 探测公网 `/v1/models`；无 Key 返回 `401` 属于预期，说明公网入口已到达网关鉴权层。
- 安装并启动网关常驻服务。
- 启动、停止、重启网关服务。
- 重启 Cloudflare Tunnel。
- 查看网关运行日志、网关常驻 stdout / stderr、Cloudflare Tunnel 日志、Cloudflare launchd stdout / stderr、桌面主进程日志。

## 4. 推荐公网运行方式

公网共享试运行时建议保持：

- Cloudflare Tunnel 常驻服务运行中。
- 网关常驻服务运行中。
- Public Base URL 指向 `https://gateway.henery.top/v1`。
- Cloudflare Public Hostname 只匹配 `^/v1`。
- 网关内只给公网成员分发独立 API Key，不复用管理员自用 Gateway Key。

重启电脑后，登录当前 macOS 用户即可由 LaunchAgent 拉起 Tunnel 和网关。网络切换或短暂断网时，Cloudflare Tunnel 会尝试重连；网关服务本身只监听本机端口，不依赖固定外网 IP。

## 5. 排障顺序

1. 在“运维与日志”确认网关服务是否运行，`http://127.0.0.1:8787/healthz` 是否健康。
2. 确认 Cloudflare Tunnel 是否运行，日志中是否有 connected / registered connection。
3. 复制公网 `/v1/models` 探测命令，无 Key 返回 `401` 为正常。
4. 携带公网成员 API Key 继续验证 `/v1/models`、非流式对话和 `stream: true`。
5. 若端口被占用，先看运维页的端口进程；只有明确是旧网关进程才允许停止。
