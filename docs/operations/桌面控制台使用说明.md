# 桌面控制台使用说明

本文档说明 `Local AI Gateway` Electron 桌面端当前已经具备的界面能力、推荐使用路径，以及现阶段仍处于预留状态的入口。

## 1. 当前定位

桌面端现在的定位是“本地 AI Gateway 操作台”，而不是聊天窗口。

它主要负责：

- 查看 gateway 服务状态与默认模型路由
- 展示桌面端自己管理的 Codex 账号
- 展示 OpenClaw 已登录的可复用本地授权
- 通过浏览器 OAuth 或 JSON 文件导入 Codex 账号
- 在界面内填写 OpenAI-compatible / Ollama provider 配置
- 复制 OpenClaw 接入片段
- 查看 provider 诊断与最近错误

实际发起对话的客户端仍然是 OpenClaw。

## 2. 页面结构

当前桌面端分为四个主区域：

- `总览`：服务状态、默认 provider、默认模型、OpenClaw Base URL、桌面端 Codex 账号数与 OpenClaw 可复用授权数
- `账号`：展示桌面端 Codex 账号，以及 OpenClaw 可复用授权，并支持切换活动授权
- `配置`：图形化填写 OpenAI-compatible / Ollama 参数，保存后自动重启服务
- `诊断`：查看每个 provider 的启用状态、缺失项与最近错误

## 3. 如何配置 Provider

### 3.1 Codex

Codex 当前不需要手动填写 `API Key`。

当前版本支持两类对象：

- `桌面端 Codex 账号`
  - 通过浏览器 OAuth 直接导入
  - 通过本地 JSON / `auth-profiles.json` 文件导入
- `OpenClaw 可复用授权`
  - 自动读取本机 `~/.openclaw/agents/*/agent/auth-profiles.json`

这里需要注意一层语义：

- `OpenClaw 可复用授权` 不是“本应用自己的 Codex 账号”
- 它表示 OpenClaw 当前机器上已经登录好的 Codex OAuth 凭据，技术上可以被 gateway 复用
- 如果多个 OpenClaw agent 共享同一个 `accountId`，桌面端会按 `accountId` 聚合成一个授权卡片
- 如果你希望把某个 OpenClaw 授权变成本应用自己管理的账号，可点击“导入为桌面端账号”

桌面端账号面板会将“桌面端 Codex 账号”和“OpenClaw 可复用授权”分开展示，并显示各自数量。

因此 Codex provider 的主要操作是：

- 查看已导入的桌面端 Codex 账号
- 查看 OpenClaw 已登录的可复用授权
- 导入新的桌面端 Codex 账号
- 将 OpenClaw 授权导入为桌面端账号
- 切换当前活动授权
- 把 `codex-default` 作为默认模型暴露给 OpenClaw

### 3.1.1 如何添加 Codex 账号

点击桌面端右上角或总览区的“添加 Codex 账号”后，可看到四个页签：

- `OAuth 授权`
- `Token / JSON`
- `API Key`
- `扫描 OpenClaw`

当前已经真正可用的是：

- `OAuth 授权`：点击按钮后自动打开浏览器完成 OpenAI Codex 授权；若本地回调未自动完成，可手动粘贴回调地址继续
- `Token / JSON`：可导入常见 JSON 结构，包括 OpenClaw `auth-profiles.json`
- `扫描 OpenClaw`：重新扫描当前机器上的 OpenClaw 本地授权

当前仍属于预留位的是：

- `API Key` 页签

### 3.2 OpenAI-compatible

在桌面端 `Provider 配置` 区块中填写：

- 启用此 Provider
- 显示名称
- 模型别名
- Base URL
- API Key
- 上游模型名
- 展示名称

保存后桌面端会调用本地 Admin API 写入配置，并自动重启 gateway。

### 3.3 Ollama

在桌面端 `Provider 配置` 区块中填写：

- 启用此 Provider
- 显示名称
- 模型别名
- Base URL
- 模型名
- 展示名称

保存后同样会自动重启 gateway。

## 4. 配置优先级

当前版本的 provider 配置优先级如下：

1. 环境变量
2. 桌面端保存的本地配置
3. 内置默认值

也就是说：

- 如果某个 provider 同时在环境变量和桌面端表单里都配置了，运行时会优先使用环境变量
- 桌面端更适合本地长期使用、且不想每次开终端手动 `export` 的场景

## 5. 本地配置保存位置

桌面端保存的本地配置位于：

```txt
~/Library/Application Support/local-ai-gateway/config.json
```

导入的本地 Codex 账号位于：

```txt
~/Library/Application Support/local-ai-gateway/codex-auth-profiles.json
```

说明：

- 这些配置只保存在本机，不会写入仓库
- 日志默认会脱敏，不记录 `Authorization`、token、cookie
- 后续版本可继续把独立密钥迁移到更安全的 Keychain 存储

## 6. Codex 账号面板当前状态

当前账号面板已经支持：

- 分开展示桌面端 Codex 账号与 OpenClaw 可复用授权
- 从 OpenClaw 授权一键导入为桌面端 Codex 账号
- 展示当前活动授权
- 切换当前活动授权
- 复制 OpenClaw 接入片段

说明：

- 桌面端导入成功的 Codex 账号会显示在“桌面端 Codex 账号”区域
- OpenClaw 已登录授权会显示在“OpenClaw 可复用授权会话”区域
- OpenClaw 来源会按 `accountId` 聚合展示，不按 agent 数量直接出卡
- 如果同一个账号同时存在于 OpenClaw 来源和桌面端导入来源，当前会按两类对象分别展示，不做自动去重

当前仍为预留位的内容：

- 真正的“剩余额度”
- 真正的“额度重置时间”
- API Key 导入 Codex 账号闭环

所以如果你看到“待接入”或“即将支持”，表示这个入口已经按未来产品形态预留，但当前版本尚未接上真实数据流。

## 7. 推荐使用路径

推荐的日常使用顺序：

1. 启动桌面端
2. 在 `总览` 中确认本地服务健康
3. 在 `账号` 中确认桌面端 Codex 账号或 OpenClaw 可复用授权是否可用
4. 如需新增 Codex 账号，可在“添加 Codex 账号”中使用 OAuth 或 JSON 导入
5. 如有需要，在 `配置` 中启用 OpenAI-compatible 或 Ollama
6. 点击“保存并重启服务”
7. 将 OpenClaw 的 `baseUrl` 指向 `http://127.0.0.1:8787/v1`
8. 在 OpenClaw 中选择对应模型别名开始使用

## 8. 当前边界

- 桌面端仍然是控制面，不承担聊天会话 UI
- 多 Codex 账号卡片位已经可用，但额度监控尚未完成
- 当前 provider 表单属于本机单用户配置，不涉及多设备同步
