# 桌面控制台使用说明

本文档说明 `Local AI Gateway` Electron 桌面端当前已经具备的界面能力、推荐使用路径和公网共享运行要点。

## 1. 当前定位

桌面端现在的定位是“本地 AI Gateway 操作台”，而不是聊天窗口。

它主要负责：

- 查看 gateway 服务状态与默认模型路由
- 查看 Token 用量总览（历史累计 / 近 24 小时 / 7 天 / 30 天）
- 查看账号级 Token 用量排行，以及账号 / 客户端 / 模型明细弹窗
- 查看路由命中观测（支持 5 分钟 / 1 小时 / 24 小时窗口切换）
- 查看账号活动观测摘要（近 5 分钟 / 1 小时 / 24 小时请求、活跃账号与主要来源）
- 展示桌面端自己管理的 Codex 账号
- 展示并导入本机已发现的可复用本地授权（当前首版优先兼容 OpenClaw 已登录会话）
- 通过浏览器 OAuth 或 JSON 文件导入 Codex 账号
- 在界面内填写 OpenAI-compatible / Ollama provider 配置
- 复制第三方客户端接入模板
- 查看 provider 诊断与最近错误
- 在诊断页查看“暂无第三方流量 / 策略未命中 / 接入鉴权缺少密钥或密钥错误”等高频问题提示
- 清理运行态遥测（会清路由命中、会话活动、号池运行态观测与熔断状态；不会清 Token 用量、访问告警事件、成员、Key、账号和配置）
- 查看账号来源分布中的“累计来源”与“近 5 分钟 / 1 小时 / 24 小时窗口”
- 查看账号近 1 小时 / 近 24 小时请求数，区分瞬时命中与持续占用
- 配置“号池调度”，把多个桌面端账号组成动态号池，供命中的策略路由自动切号
- 查看号池运行时观测：包括当前首选账号、可选成员数、冷却成员数、最近失败与最近命中时间
- 查看网关常驻服务、Cloudflare Tunnel、公网探测和本地日志，并执行启动 / 停止 / 重启等运维操作

实际发起对话的仍然是接入到本地网关的第三方客户端。当前主接入对象优先是 OpenClaw、Hermes；localRagHub 保留为次要兼容对象。

## 2. 页面结构

当前桌面端主区域：

- `总览`：服务状态、默认 provider、默认模型、网关 Base URL、桌面端 Codex 账号数、本地授权源数，以及 Token 用量总览、账号活动观测摘要
- `访问与密钥`：承载本机自用、局域网共享、公网成员 API key、额度和策略配置；可展示共享开启状态、访问者与 key 脱敏摘要，并已支持新增成员、编辑成员基础信息、创建多把成员 Key、查看成员详情和管理 key 状态
- `账号资产`：展示桌面端 Codex 账号，并支持切换活动授权、导入配置、同步额度和删除本项目本地账号副本
- `号池与路由`：定义多个桌面端账号组成的动态号池；号池列表采用紧凑表格展示，新增 / 编辑号池通过宽弹窗完成并直接保存到网关，弹窗表单按基础信息、调度保护、池成员分区对齐，池成员账号卡片压缩展示 ID、额度、重置时间和进度条
- `模型与 Provider`：图形化填写 Codex / OpenAI-compatible / Ollama 参数，配置区采用 Codex 主卡 + 扩展 Provider 单列卡片，每个 Provider 独占一行，保存后自动重启服务
- `用量与告警`：集中展示 Token 用量、成员消耗、模型 / 号池统计和告警；默认“成员观测”，可在成员 / 模型 / Key 与号池 / 总览之间切换；成员健康度卡片会展示最近活跃时间；告警与治理摘要、告警事件列表在弹窗中查看和处理
- `消息通知`：站内通知中心，用于集中查看由访问告警事件派生的系统消息；左侧导航会展示未读数字徽标，页面内支持全部 / 未读 / 已读筛选、单条标为已读、全部标为已读，并可从消息卡继续确认未处理告警；warning / critical 级别未读访问告警会尝试触发 macOS 原生通知
- `运维与日志`：查看网关 LaunchAgent、Cloudflare Tunnel、公网 `/v1/models` 探测和本地日志；安装常驻、启动 / 停止 / 重启网关、重启 Tunnel、刷新和公网修复统一收敛到页面顶部按钮组；账号健康与路由解释会展示剩余总额度、额度风险和号池覆盖等 KPI
- `系统与诊断`：查看高价值运行摘要、核心诊断、LAN / 公网共享健康检查，以及桌面端系统配置与数据迁移恢复入口；系统配置已按双列配置台重排“推理鉴权 / 请求内容留痕 / 共享入口 / 客户端密钥映射 / 桌面运行与数据”，LAN 模板、公网模板、公网验收和常见失败原因改为大弹窗查看

- 当前“开机自启、自动刷新、导入 / 导出配置、迁移恢复、运行诊断”等配置型维护能力，继续收敛在 `系统与诊断` 页；服务启停、Cloudflare 连通性和日志查看收敛在 `运维与日志` 页

- 系统配置页的“保存本页配置”会同时保存系统运行参数、第三方接入鉴权、“局域网共享”开关和三期“公网共享入口”配置；只有网关端口变化等运行参数需要重启托管网关，访问成员、成员 Key、限额、号池授权、局域网共享开关、公网入口配置和号池 / 路由配置保存后会写入运行配置并影响后续请求；`/admin/*` 管理面仍只允许本机访问，成员只能访问受 API key 保护的 `/v1/*` 推理面

- 点击状态栏图标展开菜单时，桌面端会主动刷新一次当前账号额度；即便主窗口未打开，也能尽量看到最新额度值。
- 安装版如果在某些系统环境下出现标准输出不可写，桌面主进程会自动忽略这类 `EIO / EPIPE` 日志输出错误，避免弹出重复的主进程异常提示窗。
- 当前安装版还会在 `stdout/stderr.write` 与主进程 `uncaughtException` 层面二次过滤这类输出流异常；如果仍出现弹窗，通常不再是日志输出链路，而是其他真实主进程错误。
- 安装版桌面主进程当前会优先把内部日志写入 `Application Support/local-ai-gateway/logs/desktop-main.log`；若仅删除 `.app` 重装，原日志也会继续保留并可用于排查启动问题。

## 3. 如何配置 Provider

### 3.1 Codex

Codex 当前不需要手动填写 `API Key`。

当前版本支持两类对象：

- `桌面端 Codex 账号`
  - 通过浏览器 OAuth 直接导入
  - 通过本地 JSON / `auth-profiles.json` 文件导入
- `本地可复用授权`
  - 当前首版默认读取本机 `~/.openclaw/agents/*/agent/auth-profiles.json`

这里需要注意一层语义：

- `本地可复用授权` 不是“本应用自己的 Codex 账号”
- 它表示当前机器上已经登录好的 Codex OAuth 凭据，技术上可以被 gateway 复用
- 当前首版里，这类可复用授权大多来自 OpenClaw 已登录会话
- 如果多个 OpenClaw agent 共享同一个 `accountId`，桌面端会按 `accountId` 聚合成一个授权卡片
- 如果你希望把某个已发现的本地授权变成本应用自己管理的账号，可点击“导入为桌面端账号”

桌面端账号面板默认只展示“桌面端 Codex 账号”。可复用授权作为导入来源存在，不再默认单独出卡展示。

因此 Codex provider 的主要操作是：

- 查看已导入的桌面端 Codex 账号
- 扫描并复用本机可用授权来源
- 导入新的桌面端 Codex 账号
- 将本地授权导入为桌面端账号

当前仍属于预留位的是：

- `API Key` 页签

## 3.4 号池调度

“号池调度”是三期新增模块，用于把多个桌面端 Codex 账号编成一个动态号池，供命中的请求自动切号。

需要明确区分：

- `策略路由`：决定哪类请求走哪个目标
- `号池调度`：决定号池内部最终用哪个账号

当前推荐使用方式：

1. 先在“号池与路由”页定义一个号池
2. 设置号池可见性：`private` 用于管理员自用，`shared-lan` 作为二期局域网共享候选，`public-ready` 用于三期公网成员；LAN 成员不会被分配到 `public-ready`，公网成员必须使用 `public-user` 类型和独立成员 Key
3. 通过可视多选面板勾选多个桌面端 Codex 账号作为池成员；面板支持搜索、排序、全选、反选与收起，适合大量账号场景
4. 设置额度阈值、冷却时间、单次请求最多尝试账号数
5. 再到左侧“策略路由”页，把某条规则的目标模式改成“号池调度”，并绑定到对应号池
6. 仅在某个账号暂未出现在上方列表里时，再使用“额外成员标识（高级）”手动补充 `sessionId / profileId / accountId`
7. 保存后可直接在号池卡片内观察当前首选成员、冷却状态、最近失败分类与最近选中时间
8. 号池卡片提供“查看最近调度事件”入口，点击后会以弹窗方式查看最近一次选号与自动切号原因，避免事件列表长期占据页面空间
9. 号池成员卡片会直接显示“当前未轮到 / 已跳过 / 本轮已选中”的解释文案，优先帮助你在页面上理解当前调度结论

路由预演支持在“访问成员”下拉中选择某个成员：

- 预演结果会同时展示路由命中规则、解析模型 / 会话 / 号池，以及访问策略判定
- 访问策略判定当前覆盖模型权限、允许号池、LAN 成员 `shared-lan` 可见性约束和成员基础状态
- 该预演只读取本项目内访问成员与号池配置，不读取或改写 Cockpit / OpenClaw 原始配置

号池列表支持批量管理：

- 可在号池列表顶部“选择全部号池”，也可在每张号池卡片标题左侧单独勾选
- 可一键清空当前选择
- 可批量删除已选号池，删除前会二次确认
- 批量删除与单个删除一致：二次确认后会直接删除并保存到网关；如果策略路由仍引用被删除号池，需要同步检查路由配置

当前第一版边界：

- 只纳入桌面端导入账号
- 新建号池默认 `private`；可见性和成员“允许号池”不会绕过 LAN 开关或 API key 鉴权，LAN 成员实际只能进入 `shared-lan` 动态号池，private 号池继续作为管理员自用保护区
- 访问成员列表采用可横向滚动的宽表格展示，最右侧操作列会固定在右侧；行内展示成员名称、`clientTag`、备注、Key 可用数、脱敏 Key 前后缀、额度、QPS / 并发、策略到期、模型 / 号池、标签、创建时间和更新时间。点击成员行或“编辑”按钮会打开成员弹窗
- 新增 / 编辑成员共用全局弹窗，弹窗内可编辑成员基础信息，包括成员名称、`clientTag`、备注和标签；成员信息区采用紧凑身份栏布局，避免少量字段占用过多纵向空间。这些字段只保存到本项目访问控制配置中，不改写 Cockpit / OpenClaw 原始账号配置
- 访问成员弹窗可为同一成员新增多把独立 Key，可设置 Key 名称和到期时间；“API Key 管理”区域采用“新增 Key 在前、现有 Key 列表在后”的单列布局，每把 Key 独占一行展示名称、脱敏前后缀、状态、创建 / 最近使用 / 到期 / 轮换时间，并支持暂停 / 启用、保存到期、轮换和删除。新增或轮换后的完整 API Key 会在“本次生成的 Key 明文”面板中只展示一次，关闭后配置文件只保留 hash、前缀、后缀、状态和到期时间等脱敏元数据
- 访问成员弹窗可编辑的策略包括“周期包”“总量包”“不限制”三种使用方式，并按所选方式显示对应级联表单：周期包填写周期天数与周期 Token 总量，总量包填写总量 Token，不限制则隐藏 Token 额度输入；级联表单采用“使用方式 + 当前模式配置”的稳定两栏，模式配置内部按输入项和说明排列，减少切换后的错位。策略到期时间、每分钟请求数、最大并发请求、单请求输入 / 输出 Token、允许模型别名和允许号池继续作为独立配置保留。Token 额度输入当前按 `M` 为单位填写。周期包到期或额度耗尽会拒绝后续请求；总量包不限制自然天数，直到累计 Token 达到上限
- “允许模型别名”现在由两部分组成：上方可勾选当前网关已暴露的模型别名，下方可补充自定义别名；两者保存时会合并去重。留空 / 不勾选表示该成员不限制模型；若填写了别名，成员请求的 `model` 必须命中其中之一，否则推理面会返回模型权限拒绝
- 新建成员成功后弹窗会继续展示“本次生成的 Key 明文”，便于立即复制；编辑已有成员保存成功后会直接关闭弹窗
- 从成员表格点击行或“编辑”打开已有成员时，不会默认聚焦“成员名称”输入框，避免打断查看配置的视线
- 访问成员表格操作列可禁用 / 启用成员；禁用成员会保留该成员和其 API Key 元数据，但该成员名下 API Key 后续调用会被网关拒绝，不删除账号资产，也不修改 Cockpit / OpenClaw 原始账号配置
- 访问成员表格操作列可删除成员；删除前会二次确认，确认后会删除本项目访问控制配置中的成员、关联 AccessKey 和成员策略，因此旧 API Key 将无法继续通过本地网关鉴权；该操作不删除账号资产，不修改 Cockpit / OpenClaw 原始账号配置
- 访问成员弹窗内可删除单把 API Key；删除前会二次确认，确认后仅移除本项目访问控制配置中的该 Key，使旧 Key 失去网关调用能力，不删除访问成员、账号资产或 Cockpit / OpenClaw 原始配置
- 配置周期包或总量包后，推理面会按成员累计用量执行拦截；旧版日 Token 限额仍兼容执行，访问成员详情中的近 24 小时快照继续作为短窗口观测参考
- 当前周期包、总量包、日 Token 兼容限额、策略到期时间、QPS、并发、单请求输入 / 输出 Token、允许模型和允许号池已进入服务端执行层；月 Token 限额当前先保留管理端保存兼容项，后续再决定是否恢复为自然月硬包
- 配置 QPS 或最大并发后，访问成员详情会基于 `/admin/health` 的运行态摘要展示近 60 秒请求数、当前 in-flight 数、剩余容量和状态进度条
- 动态号池命中的推理请求会写入 `poolId` 用量归因，用量与告警页可在维度洞察和用量明细弹窗中查看号池排行；未命中动态号池的自用或固定账号请求不会强行归入号池
- `usageSummary.daily` 会输出按小时聚合的访问成员、模型、Access Key 和号池趋势桶；用量与告警页日窗口会优先展示成员 24h Token 趋势，并可通过“全部 / 成员 / 模型 / Key / 号池”维度选择聚焦 Top 模型、Top Access Key 和 Top 号池的 24h Token、请求数、失败率和峰值小时，周 / 月 / 总窗口仍展示窗口 Token 结构
- 访问 key、成员和策略类拒绝会写入 `access_alert_events`，管理端 `/admin/access/alerts` 可查询最近事件，并可通过 `/admin/access/alerts/clear-acknowledged` 清理已确认事件；同一维度的未确认告警会合并计数并更新最近发生时间，运行时按 90 天 / 5 万行做轻量清理；该表只属于本项目本地观测数据，不写入 Cockpit / OpenClaw
- 不直接把原始本地可复用授权当作正式池成员
- 不把多个账号做成真正的“额度池化”；单次请求仍只会使用一个账号
- 请求级自动切号不会修改全局活动账号
- 流式请求只在首个字节输出前允许自动切到下一个候选

## 4. 配置优先级

当前版本的 provider 配置优先级如下：

1. 环境变量
2. 桌面端保存的本地配置
3. 内置默认值

也就是说：

- 如果某个 provider 同时在环境变量和桌面端表单里都配置了，运行时会优先使用环境变量
- 桌面端更适合本地长期使用、且不想每次开终端手动 `export` 的场景

## 5. 本地配置保存位置

桌面端保存的本地配置位于：

```txt
~/Library/Application Support/local-ai-gateway/config.json
```

导入的本地 Codex 账号位于：

```txt
~/Library/Application Support/local-ai-gateway/codex-auth-profiles.json
```

说明：

- 这些配置只保存在本机，不会写入仓库
- 日志默认会脱敏，不记录 `Authorization`、token、cookie
- 后续版本可继续把独立密钥迁移到更安全的 Keychain 存储

## 6. Codex 账号面板当前状态

当前账号面板已经支持：

- 默认只展示桌面端 Codex 账号，减少重复账号信息干扰
- 在账号模块内直接添加 Codex 账号
- 通过“导入账号配置信息”直接导入 Cockpit Tools 多平台导出文件中的 Codex 账号，也可导入顶层 token 数组或 sub2api 风格账号导出
- 从已发现的本地授权一键导入为桌面端 Codex 账号
- 通过本项目浏览器 OAuth 授权新增的账号由 `local-ai-gateway` 托管，可在 access token 过期时由本项目刷新
- 通过 JSON / Cockpit / OpenClaw 文件导入的账号默认是外部只读凭据，不会由本项目主动刷新 refresh token；若 Cockpit 侧重新授权或刷新后恢复，需要重新导出并导入，或后续接入外部源同步机制
- 账号卡片标题优先显示邮箱账号名，其次回退到显示名、账号 ID
- 账号卡片不再展示标题下方的内部 ID，正文只保留关键信息
- 对导入时带有元数据快照的账号，显示邮箱、套餐、额度百分比与重置时间
- 额度区会显式区分窗口类型、重置时间和最近同步时间
- 顶部“刷新状态”是全局刷新入口：主动同步本地网关状态、运行态摘要和可刷新账号的实时额度；外部只读账号不会因此刷新 refresh token
- `用量与告警` 页提供独立“刷新用量”按钮，只刷新 Token 用量、访问告警和图表分析，适合排查成员消耗、额度告警和图表时效，不会触发整套账号额度同步
- 支持账号搜索，以及按剩余额度、重置时间、账号名称进行升序/降序排序（默认按剩余额度降序）
- 支持账号模块内一键同步全部账号额度
- 支持单账号行级别的“同步额度”操作
- 支持展示第三方请求活动：当某个账号最近被网关实际命中时，卡片会显示“活跃调用”提示
- 支持自动或手动观察请求活动：账号列表会定时静默刷新会话活动，但静默刷新不应重建账号表格或打断批量选择；你也可以手动点击“刷新状态 / 同步额度”立即看到最新状态
- 支持同时观察短时与长时活动：账号卡片会显示累计来源、近 5 分钟来源，以及近 1 小时 / 近 24 小时请求数
- 支持从“账号资产摘要”面板观察近 5 分钟 / 1 小时 / 24 小时来源窗口、额度充足度分布与最忙账号
- 支持删除桌面端本地导入账号
- 支持批量勾选并删除桌面端本地账号；删除会真正移除 `local-ai-gateway` 本地 `codex-auth-profiles.json` 中对应账号副本
- 删除本地账号时，会同步清理“号池调度”中引用该账号的成员标识，避免存量号池继续指向已不存在账号
- 如果账号来自 Cockpit / OpenClaw / JSON 导入，删除仅影响本项目本地副本，不会删除或改写 Cockpit / OpenClaw 原始配置文件
- 所有刷新按钮都带有运行中 loading 状态，避免重复触发
- 账号卡片直接使用桌面主进程本地会话数据，不再依赖 gateway 会话接口版本
- 展示当前活动授权
- 切换当前活动授权
- 复制第三方接入模板
- 通过更紧凑的卡片布局在有限空间内容纳更多账号
- 卡片类元素统一补充阴影与悬浮动效，提升列表浏览反馈

当前顶部状态区还会额外展示：

- 服务概况
- 当前路由模型
- 当前活动授权
- 当前 Provider / 授权对象数量

当前加载与刷新策略：

- 控制台初始化时会优先加载界面主体，再在后台同步实时额度
- 因此首屏可见速度会快于“先等所有额度刷新完成再显示”
- 多账号场景下，实时额度刷新已从串行请求调整为限流并发执行
- 额度刷新默认只针对“桌面端 Codex 账号”执行，不再将仅作为导入来源的本地可复用授权计入失败统计
- 对外部只读凭据，额度刷新只会优先复用现有 access token 拉取快照；如果 access token 失效，不会用 refresh token 重试，避免影响 Cockpit / OpenClaw 等外部工具的账号状态
- 静默轮询除账号活动外，也会同步刷新路由命中观测与顶部摘要，因此第三方请求经过后，路由观测无需再依赖手动刷新才可见

另外：

- 如果某个账号额度刷新失败，桌面端会在“最近错误”区直接显示失败会话与失败原因
- `诊断` 页新增“服务分层诊断”，会明确区分端口冲突、网关未响应、活动账号异常等不同故障类型
- 如果开启了局域网共享，诊断页会额外提示当前 LAN Base URL，并检查是否存在可用接入 Key、`shared-lan` 号池、启用中的 LAN 成员和成员 API Key；LAN Base URL 来自桌面端健康检查实时枚举到的本机局域网 IP，换网或 IP 变化后通常无需重启 gateway，等待下一次状态刷新或手动点击“刷新状态”即可更新展示；同时会提示监听地址、局域网 IP、端口 / 防火墙人工验证、管理员主机睡眠和外网预留边界，并提供只含占位 API Key 的 LAN 成员接入模板
- LAN 成员接入模板里的 `model` 会优先使用当前默认模型；可用值来自 Provider 注册表 / 模型配置中已暴露的别名，例如默认 Codex 别名 `codex-default`，以及当前 Codex 暴露配置中的 `codex-5.5 / codex-5.4 / codex-5.4-mini / codex-5.3 / codex-5.2` 等。实际可用列表以界面“模型与 Provider”页和 `/v1/models` 返回值为准
- 若额度同步失败，账号卡片会显示“额度同步失败”标签和原因；这不等同于账号 OAuth 不可用

说明：

- 桌面端导入成功的 Codex 账号会显示在“桌面端 Codex 账号”区域
- 本机可复用授权会作为导入来源参与账号管理，不再默认单独出卡
- 导入来源会按 `accountId` 聚合，避免重复导入同一账号时产生大量冗余卡片

当前仍为预留位的内容：

- 更稳定的自动轮询刷新与失败重试
- 多窗口额度同时展示（例如 5 小时窗口与 7 天窗口）
- API Key 导入 Codex 账号闭环

## 6.1 系统配置栏

当前 `诊断` 页已新增系统配置栏，支持：

- 开机自启动
- 自动刷新时间间隔
- 网关端口
- 第三方客户端接入鉴权（`none / api-key`）
- 应用数据导出 / 导入 / 迁移恢复

说明：

- 自动刷新默认 2 分钟一次，可在界面中调整
- 自动刷新会在后台同步账号额度与状态，不要求你手动点击“刷新状态”；后台自动刷新不应弹出成功 / 失败横幅打断当前操作，失败细节优先沉淀到账号状态或排障视图
- 会话活动静默轮询当前为 30 秒一次；当你正在“访问与密钥”页或新增成员弹窗中编辑表单时，后台刷新只更新内存状态，不会重绘并清空正在填写的访问成员、Key 或策略配置草稿
- 开机自启动仅在打包版中实际注册；开发态会保留配置值，但不会尝试写入系统登录项，以避免本地调试阶段触发系统权限报错
- 网关端口默认是 `8787`，保存后托管网关会按新端口自动重启
- 若端口被其他进程占用，桌面端会给出明确提示并建议更换端口或释放端口
- 若开启 `api-key` 鉴权，第三方客户端调用 `/v1/models` 与 `/v1/chat/completions` 时必须携带密钥
- 鉴权开启后，复制接入片段会自动提示 `apiKey` 字段；本机自用可填 Gateway API Key，LAN 成员应填写分发给该成员的一次性 API Key 明文
- 错误码 `401/403/503` 的含义与排查方式见《第三方客户端接入模板与错误排查》
- `总览 -> 第三方接入模板` 提供 OpenClaw / Hermes / 通用 cURL 的一键复制入口，可直接用于接入或联调
- `localRagHub` 仍可接入，但当前在产品叙事与模板主位上已降级为次要兼容对象
- `诊断与系统` 页顶部的“首次启动检查 / 升级与发布前建议”会根据当前状态动态提示最值得优先确认的步骤

### 6.2 数据迁移与恢复

当前桌面端支持在 `诊断 -> 系统配置 -> 数据迁移与恢复` 中：

- 导出当前本机应用数据为单文件备份
- 在重装或迁移后重新导入旧数据
- 导入前自动生成本机安全备份，便于误覆盖后回滚
- 直接打开本机安全备份目录
- 查看当前本地数据概况与最近一次安全备份信息

补充说明：

- 导入前会先展示备份的导出时间、应用版本、文件数和总体积，再由你确认是否覆盖当前本机数据
- 如果当前 gateway 由桌面端托管，导入完成后会尝试自动重启托管 gateway；否则会提示手动重启外部进程

详情见：[数据导出与迁移恢复](/local-ai-gateway/docs/operations/数据导出与迁移恢复.md)

### 3.1.2 如何切换 Codex 上游模型

当前桌面端已经支持在 `Provider 配置 -> Codex Provider` 中切换 `codex-default` 背后的上游模型。

当前内置支持：

- `gpt-5.5`
- `gpt-5.4`
- `gpt-5.4-mini`
- `gpt-5.3-codex`
- `gpt-5.2`

说明：

- 当前切换的是 `codex-default` 对应的真实上游模型
- 当前也支持并行暴露多个 Codex 模型别名
- 第三方客户端里的 `model` 应填写本项目对外暴露的模型别名，而不是上游原始模型名；可在“模型与 Provider”页查看，也可通过 `/v1/models` 验证
- 保存后会自动重启 gateway 生效

所以如果你在外网共享等三期入口看到“待接入”或“即将支持”，表示该入口只是未来产品形态预留；局域网共享二期入口不应再显示“待接入”，应按真实配置显示默认关闭、缺少 Key 或二期可用。

## 7. 推荐使用路径

推荐的日常使用顺序：

1. 启动桌面端
2. 在 `总览` 中确认本地服务健康
3. 在 `账号` 中确认桌面端 Codex 账号是否可用
4. 如需新增 Codex 账号，可在“添加 Codex 账号”中使用 OAuth 或 JSON 导入
5. 如有需要，在 `配置` 中启用 OpenAI-compatible 或 Ollama
6. 点击“保存并重启服务”
7. 将第三方客户端的 `baseUrl` 指向 `http://127.0.0.1:8787/v1`
8. 在第三方客户端中选择对应模型别名开始使用；若你接入的是 OpenClaw 或 Hermes，可直接使用总览里的对应模板

## 8. 当前边界

- 桌面端仍然是控制面，不承担聊天会话 UI
- 多账号场景已支持额度快照、来源窗口与账号资产摘要，但“额度变化与具体来源的直接因果归因”仍属于后续增强项
- 当前 provider 表单属于本机单用户配置，不涉及多设备同步
