# 安装与升级检查清单

本文档用于说明 `Local AI Gateway` 在以下场景下的推荐检查顺序：

- 首次启动桌面端
- 升级版本后重新验证
- 从源码重新构建、打包或迁移到新机器后验证

## 1. 首次启动检查

建议按以下顺序确认：

1. 启动桌面端后，先在 `总览` 中确认顶部状态为“服务运行中”。
2. 确认 `网关 Base URL` 与 `接入片段模型` 已正确显示。
3. 在 `账号资产` 中确认至少已有一个可用桌面端 Codex 账号。
4. 如当前仍未选择活动账号，请先将一个可用账号设为活动账号。
5. 使用 `总览 -> 第三方接入模板` 复制对应模板，完成一次真实第三方联调。
6. 联调后回到桌面端，确认账号卡片中的：
   - 请求数
   - 来源分布
   - 近 5 分钟来源
   - 路由命中观测
   已开始更新。

如果上述 1 至 6 步都已满足，则说明“本地网关 -> Codex 账号 -> 第三方客户端”这条主链路已经跑通。

## 2. 升级后检查

版本升级后，建议最少确认这些内容：

1. 打开 `诊断与系统`，查看是否出现新的运行诊断或 Provider 诊断异常。
2. 检查当前 `第三方客户端接入鉴权` 是否仍符合你的使用方式。
3. 如果升级后改动了网关端口，请同步修改所有第三方客户端中的 `baseUrl`。
4. 用一个最短请求重新验证：
   - 第三方能否成功调用
   - 路由命中是否更新
   - 账号卡片请求数与来源标签是否更新
5. 如果你使用了策略路由，请在左侧 `策略路由 -> 路由预演` 中再做一次预演，确认规则仍然命中预期账号。

## 3. 源码版发布前检查

如果你是从源码运行、准备打包或准备交付新的桌面包，建议执行：

```bash
npm run preflight:release
```

该命令会依次执行：

1. `npm run build`
2. `npm test`
3. `npm run smoke:gateway`
4. `npm run smoke:desktop-package`

说明：

- `smoke:gateway` 用于验证本地网关主链路是否正常
- `smoke:desktop-package` 用于验证目录包能否生成，以及 `.app / Info.plist / app.asar` 是否齐全

## 4. 当前已知限制

- 当前仍未接入正式的 notarization 流程
- 当前仍使用默认 Electron 图标
- `smoke:desktop-package` 的目标是做资源级验收，不替代正式的签名 / 公证发布

## 5. 推荐入口

如果你希望直接在桌面端查看当前状态，可优先看：

- `诊断与系统 -> 首次启动检查`
- `诊断与系统 -> 升级与发布前建议`
- `总览 -> 路由命中观测`
- `总览 -> 账号活动观测`
