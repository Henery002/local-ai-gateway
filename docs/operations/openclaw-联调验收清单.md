# OpenClaw 联调验收清单

本文档用于在不打断现有工作流的前提下，对 `OpenClaw -> Local AI Gateway -> Codex` 链路做一次低扰动、可回滚、可复盘的真实验收。

## 1. 验收目标

本次联调只验证最关键的闭环：

- OpenClaw 请求确实发到了本地网关
- 网关桌面端能把该请求识别为 `openclaw`
- 策略路由能按预期命中
- 活动账号切换或固定账号规则能按预期生效

本次联调不追求大规模压测，也不建议在生产中的长任务执行期间做侵入式测试。

## 2. 联调前提

建议先满足以下条件：

- 本地网关桌面端能正常打开，且 `总览 -> 服务状态` 为运行中
- 账号页至少存在 1 个可用桌面端 Codex 账号
- 如果准备测试固定账号路由，目标账号当前应为可用状态
- OpenClaw 当前没有正在执行中的关键任务

## 3. 联调前的零扰动检查

先执行配置审计：

```bash
npm run audit:openclaw
```

期待结果：

- `openclaw.json` 检查通过
- `main / builder / sentry / ops` 等 agent 的 `models.json` 检查通过
- 每个目标 agent 都能找到指向 `http://127.0.0.1:8787/v1` 的本地网关 Provider
- 每个目标 agent 都带有 `x-client-tag=openclaw`

再执行网关基础 smoke：

```bash
npm run smoke:gateway
```

这一步主要验证本地网关自身没有坏，不等于验证 OpenClaw 已真实接入。

## 4. 两种推荐联调模式

### 4.1 灵活切号版

适用场景：

- 你希望 OpenClaw 始终走 `codex-default`
- 但具体使用哪个账号，由桌面端“当前活动账号”控制

推荐策略规则：

- 客户端标签：`openclaw`
- 请求模型别名：`codex-default`
- 目标模型别名：`codex-default`
- 目标会话 / 账号标识：留空

这意味着：

- OpenClaw 的请求会被识别为一类独立流量
- 但仍然跟随桌面端当前活动账号
- 以后切号时，只需要切换“当前活动账号”，无需改路由规则

### 4.2 固定专用账号版

适用场景：

- 你希望 OpenClaw 永远吃某一个专门的 Codex 账号
- 不希望它受桌面端日常切号影响

推荐策略规则：

- 客户端标签：`openclaw`
- 请求模型别名：`codex-default`
- 目标模型别名：`codex-default`
- 目标会话 / 账号标识：填写目标账号标识

这意味着：

- 只要命中该规则，OpenClaw 就固定走这个账号
- 此时桌面端切换“当前活动账号”，不会影响该条 OpenClaw 流量

## 5. 最小扰动验收步骤

### 步骤 1：记录当前状态

在桌面端记录以下信息：

- 当前活动账号是谁
- 是否启用了策略路由
- OpenClaw 相关规则是“灵活切号版”还是“固定专用账号版”

### 步骤 2：发送一个极短请求

在 OpenClaw 中发起一个极短测试，例如：

- “只回复 OK”
- “只输出 1”

避免使用长上下文、工具调用或高 token 消耗请求。

### 步骤 3：观察桌面端账号页

重点看：

- 账号卡片中的“最近调用”是否刷新
- “请求数”是否递增
- “来源分布”是否出现 `openclaw`
- “近 5 分钟”是否出现 `openclaw`

### 步骤 4：观察路由观测面板

在 `总览 -> 路由命中观测` 中确认：

- 最近事件中出现 `openclaw`
- 命中的规则与预期一致
- 命中的模型别名仍是 `codex-default`

### 步骤 5：验证切号行为

如果你使用的是“灵活切号版”：

- 切换桌面端当前活动账号
- 再发一个极短 OpenClaw 请求
- 观察是否命中新账号

如果你使用的是“固定专用账号版”：

- 切换桌面端当前活动账号
- 再发一个极短 OpenClaw 请求
- 观察是否仍命中固定账号

## 6. 如何判定验收通过

满足以下条件即可视为本轮闭环通过：

- OpenClaw 请求能稳定通过本地网关完成
- 桌面端可观测到 `openclaw` 来源
- 路由命中结果与预演一致
- 灵活切号或固定账号行为符合预期

## 7. 已知边界

以下几点需要明确：

- OpenClaw 的 fallback 更偏向“请求级重试/回退”，不能简单理解为“长任务中途无感热切换”
- 如果你把策略路由固定到了某个账号，而该账号失效或额度异常，当前版本不会自动优雅切到别的账号继续执行
- 因此本轮联调优先验证“路由是否按预期命中”，而不是验证复杂故障转移

## 8. 回滚方式

如果本轮联调需要回滚，可按以下顺序处理：

1. 在桌面端关闭或删除 OpenClaw 专用策略规则
2. 如有必要，切回原来的活动账号
3. 若需回滚 OpenClaw 配置，可使用你本机已有的 `~/.openclaw/backups/20260327-230453/`

## 9. 建议的联调节奏

推荐节奏：

1. 先做“灵活切号版”验证
2. 再做“固定专用账号版”验证
3. 最后再考虑“固定账号失效后的回退策略”这类更高风险场景

这样最稳，也最容易定位问题。
