# 第三方客户端接入模板与错误排查

> 2026.03.27

本文档用于统一 `OpenClaw`、`Hermes` 等第三方客户端接入本地网关时的最小配置模板与错误排查方式。

你也可以直接在桌面端 `总览 -> 第三方接入模板` 中点击“复制”按钮获取对应模板（OpenClaw / Hermes / 通用 cURL）。

## 1. 接入前检查

- 本地网关已启动
- 已选择可用的活动账号
- 已确认模型别名（默认 `codex-default`）
- 若启用了 API Key 鉴权：已在桌面端系统配置中保存有效密钥
- 若使用公网入口：已启用公网共享配置，Public Base URL 为 `https://gateway.henery.top/v1`，并准备好公网成员专属 API Key

## 2. 鉴权模式说明

- `none`：不校验第三方请求密钥，适合本机单用户调试
- `api-key`：第三方请求必须携带密钥，适合多应用共享本地网关

启用位置：桌面端 `诊断与系统` -> `第三方客户端接入鉴权`

补充说明：

- `clientTag` 建议显式填写，便于在账号卡片看到来源分布
- 网关优先从请求头读取 `x-local-ai-client-tag / x-client-tag / x-source-app`
- 若接入方未显式传 `clientTag`，网关会尝试从 `User-Agent` 推断常见客户端（如 `openclaw`、`hermes`、`localraghub`）
- 从 `2026-05-01` 起，网关支持“客户端密钥映射”：
  - 可为不同客户端配置独立 API Key，并按 key 自动写入 `clientTag`
  - 开启后可减少对上游显式 `x-client-tag` 的依赖，适合 Hermes 这类不方便自定义 header 的接入场景
  - 映射项可单独控制是否允许 `x-client-tag` 覆盖（`allowHeaderOverride`）

### 2.1 客户端密钥映射（推荐长期方案）

启用位置：桌面端 `诊断与系统 -> 第三方客户端接入鉴权`。

建议配置方式：

- `Gateway API Key`：作为“兜底通用 key”，兼容未迁移客户端
- 客户端映射：为 `OpenClaw`、`Hermes` 分配独立 key 与默认标签
  - `OpenClaw` -> `clientTag=openclaw`
  - `Hermes` -> `clientTag=hermes`
- 若希望客户端上游头部仍能覆盖标签，再为该映射启用“允许 header 覆盖标签”

## 3. OpenClaw 接入模板

```ini
provider=openai
baseUrl=http://127.0.0.1:8787/v1
model=codex-default
clientTag=openclaw
# 若启用 API Key 鉴权，请加上：
# apiKey=<你的 Local AI Gateway API Key>
```

### 3.1 OpenClaw 真实配置写法

如果希望账号卡片里的“来源分布 Tag”稳定显示为 `openclaw`，推荐在 OpenClaw 的 provider 上显式写静态请求头，而不是只依赖 `User-Agent` 推断。

OpenClaw 官方配置参考已支持：

- `models.providers.<provider>.headers`

可直接写进 `~/.openclaw/openclaw.json` 的对应 provider：

```json
{
  "models": {
    "providers": {
      "openai": {
        "baseUrl": "http://127.0.0.1:8787/v1",
        "apiKey": "dummy",
        "api": "openai-completions",
        "headers": {
          "x-client-tag": "openclaw"
        }
      }
    }
  }
}
```

补充说明：

- 如果本地网关启用了 `api-key` 鉴权，OpenClaw 里的 `apiKey` 需要改成真实的网关 API Key，不能继续用 `dummy`
- `clientTag` 是本地网关用来识别“请求来自哪个第三方客户端”的标签，不会影响 OpenClaw 的正常模型调用
- 本项目网关会优先读取 `x-local-ai-client-tag / x-client-tag / x-source-app`，因此这里推荐写 `x-client-tag`

## 4. Hermes 接入模板

```yaml
model:
  provider: custom
  base_url: http://127.0.0.1:8787/v1
  default: codex-default

custom_providers:
- name: codex-default
  base_url: http://127.0.0.1:8787/v1
  model: codex-default
  # 若启用 API Key 鉴权，请额外填写：
  # api_key: <你的 Local AI Gateway API Key>
```

补充：

- 建议把 Hermes 作为本项目的主接入对象之一，并显式标记为 `hermes`。
- `localRagHub` 仍可继续接入，但当前已降级为次要对象，推荐在需要补充 RAG 场景时再配置。

## 5. 三期公网成员接入模板

当前邀请制公网 MVP 已通过 Cloudflare Tunnel 暴露 `/v1/*` 推理面，公网成员客户端填写：

```txt
Base URL: https://gateway.henery.top/v1
Model: codex-default
API Key: <公网成员 API Key>
```

通用 cURL 自检：

```bash
curl https://gateway.henery.top/v1/models \
  -H "Authorization: Bearer <公网成员 API Key>"
```

非流式对话：

```bash
curl https://gateway.henery.top/v1/chat/completions \
  -H "Authorization: Bearer <公网成员 API Key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"codex-default","messages":[{"role":"user","content":"ping"}],"stream":false}'
```

流式对话：

```bash
curl https://gateway.henery.top/v1/chat/completions \
  -H "Authorization: Bearer <公网成员 API Key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"codex-default","messages":[{"role":"user","content":"ping"}],"stream":true}'
```

Codex App / CC Switch（Responses API）：

```toml
model_provider = "custom"
model = "codex-default"

[model_providers.custom]
name = "Local AI Gateway"
wire_api = "responses"
requires_openai_auth = true
base_url = "https://gateway.henery.top/v1"
```

Responses cURL 自检：

```bash
curl https://gateway.henery.top/v1/responses \
  -H "Authorization: Bearer <公网成员 API Key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"codex-default","input":"ping","max_output_tokens":8}'
```

成员额度查询：

```bash
curl https://gateway.henery.top/v1/user/balance \
  -H "Authorization: Bearer <公网成员 API Key>"
```

CC Switch 的 Usage Query 可使用通用余额查询模板。当前公网 Base URL 建议填写 `https://gateway.henery.top/v1`，因此模板中的 `{{baseUrl}}/user/balance` 会命中本网关 `GET /v1/user/balance`。返回的 `balance / used / total` 表示本网关分配给该成员 API Key 的 Token 包额度，不表示上游 Codex / OpenAI 官方账号真实剩余额度。

为兼容更多第三方工具的额度按钮，公网成员 Key 也可查询：

```bash
curl https://gateway.henery.top/v1/backend-api/wham/usage \
  -H "Authorization: Bearer <公网成员 API Key>"

curl https://gateway.henery.top/v1/dashboard/billing/credit_grants \
  -H "Authorization: Bearer <公网成员 API Key>"
```

这两类接口同样只返回本网关成员包额度。2026-05-23 实测：CC Switch 的 `Local AI Gateway 公网` Provider 已能通过 Usage Query 展示 `已使用 / 剩余 / tokens / quota: total`；Cockpit Tools 的自定义 API_KEY 卡片当前不会自动调用自定义 Provider 额度接口，批量刷新仍只请求其内置 Codex OAuth 账号的 `chatgpt.com/backend-api/wham/usage`，因此卡片可能继续显示“暂无配额数据”。这属于 Cockpit 侧自定义 API_KEY 卡片能力边界，不表示本网关额度接口不可用。

普通商业成员不需要管理员本机的切换脚本。成员只要在自己的 CC Switch / Codex App 中新增 OpenAI-compatible / Custom OpenAI Provider，填写公网 Base URL、专属 API Key、`wire_api = "responses"`，并选择 `/v1/models` 返回且被该成员策略允许的模型别名即可。`~/Library/Application Support/local-ai-gateway/codex-provider-switch/*` 脚本只用于管理员本机在 Cockpit Tools 与本网关之间反复切换时保护已有 Codex 项目、MCP、memory 和桌面配置。

### 5.1 Codex App / CC Switch 与 Cockpit 网关无损切换

当前推荐保留两个 Codex Provider：

- `default`：指向 Cockpit Tools 本地 API 服务 `http://127.0.0.1:56267/v1`，`model_provider = "codex_local_access"`。
- `Local AI Gateway 公网`：指向本网关公网入口 `https://gateway.henery.top/v1`，`model_provider = "custom"`，`wire_api = "responses"`。

两者都必须保存为完整 Codex 配置，保留 `mcp_servers`、`projects`、`memories`、`desktop` 等配置段。不要再使用只包含 `model`、`model_provider` 和单个 `[model_providers.custom]` 的短模板；也不要为本网关切换写入 `disable_response_storage = true`。

低扰动切换方式：

```bash
# 只做预检，不写入 ~/.codex
node "$HOME/Library/Application Support/local-ai-gateway/codex-provider-switch/switch-codex-provider.mjs" local-gateway --dry-run
node "$HOME/Library/Application Support/local-ai-gateway/codex-provider-switch/switch-codex-provider.mjs" cockpit --dry-run

# 切到 Local AI Gateway 公网
"$HOME/Library/Application Support/local-ai-gateway/codex-provider-switch/switch-to-local-gateway.sh"

# 切回 Cockpit Tools
"$HOME/Library/Application Support/local-ai-gateway/codex-provider-switch/switch-to-cockpit.sh"
```

切到本网关前，脚本会确认本地网关 `/healthz` 正常，并使用公网成员 Key 验证 `https://gateway.henery.top/v1/models` 可达。切回 Cockpit 前，脚本会确认 `127.0.0.1:56267` 已监听；如果未监听，会先打开 Cockpit Tools，并要求先在 Cockpit Tools 的“多开实例”中点击 Codex 实例“启动”，再重新执行切回脚本。脚本在实际写入前会备份 `~/.codex/config.toml`、`~/.codex/auth.json` 和 `~/.cc-switch/cc-switch.db` 到：

```txt
~/Library/Application Support/local-ai-gateway/backups/codex-provider-runtime-switch-*
```

也可以在 CC Switch 中直接点击 `default` 与 `Local AI Gateway 公网` 切换，但建议首次切换后确认 `~/.codex/config.toml` 仍包含 `mcp_servers / projects / memories / desktop`。如果要切回 Cockpit，先确保 Cockpit Tools 的多开实例已启动，或者确认：

```bash
lsof -nP -iTCP:56267 -sTCP:LISTEN
```

每次切换后重启 Codex App 或新开 Codex 窗口，让 Codex 稳定读取新的 Provider 配置。

跨 Provider 继续既有会话的边界：

- 切换后新建会话可正常使用，说明 Provider 基础链路、`/v1/models`、`/v1/responses`、成员 Key、号池调度均已跑通。
- 继续另一 Provider 下创建过的旧会话时，Codex 会把历史工具调用、response item、call id 等上下文一起回放给当前 Provider；这些 ID 可能带有上一 Provider 的私有格式。
- 2026-05-23 已修复本网关侧超长 `call_id / tool_call_id` 兼容：本网关会在 Responses / Chat 转换和 Codex 官方上游回放前，把超 64 字符的工具调用 ID 稳定归一，并保持工具调用与工具结果成对一致。
- 仍需注意：如果历史会话里已有另一 Provider 写入的私有超长 ID，且切回该 Provider 后由它直接向官方上游回放，那么是否能无缝继续取决于该 Provider 自身是否也做同类归一。本网关不会自动改写 `~/.codex` 会话文件。
- 产品建议：跨网关切换后，关键任务优先新建会话；需要继续旧会话时，优先留在创建该会话的 Provider，或等待双方都具备同类历史 ID 归一能力。

公网侧固定边界：

- Cloudflare Tunnel Service URL 保持 `http://127.0.0.1:8787`，不要写 `/v1`
- Cloudflare Tunnel Path 保持 `^/v1`
- 不为 `/admin/*`、`/healthz` 或桌面管理面创建公网路由
- 公网成员必须是 `public-user` 类型，并使用独立公网成员 Key
- 公网成员只授权 `public-ready` 号池
- 公网成员请求会经过代码层安全阀：过大的 body、过多消息、过多工具定义、过大的工具 schema、过长单条文本或工具结果会被网关前置拒绝
- 公网成员即使未显式配置单请求 Token 上限，也有默认输入估算上限 `1050000` 和输出上限 `128000`；如需更严，可在“访问与密钥 -> 成员策略”中配置单请求输入 / 输出 Token
- 同一上游账号会按 `accountId / email / sessionId` 聚合并发与近 60 秒准入次数；多把公网成员 Key 同时打到同一账号时也会共享账号级安全阀

## 6. 错误码速查

- `401 gateway_api_key_required`
  - 含义：当前网关启用了 API Key 鉴权，但请求未携带密钥
  - 处理：在第三方客户端补齐 `Authorization: Bearer <key>` 或 `x-api-key`

- `403 gateway_api_key_invalid`
  - 含义：请求携带了密钥，但与网关配置不一致
  - 处理：核对桌面端保存的密钥与第三方客户端配置是否一致

- `403 access_policy_public_user_disabled`
  - 含义：请求来自公网成员，但本项目公网共享总开关或 HTTPS Public Base URL 条件未满足
  - 处理：确认系统配置中已启用公网共享，且 Public Base URL 为 `https://gateway.henery.top/v1`

- `403 access_policy_pool_visibility_denied`
  - 含义：公网成员命中的号池不是 `public-ready` 可见性，或默认 / LAN 成员误用了公网号池
  - 处理：核对成员类型、成员策略和号池授权，公网成员只能使用 `public-ready` 号池

- `403 access_policy_model_denied`
  - 含义：客户端请求的模型别名未被该成员策略允许，或没有出现在当前 `/v1/models` 返回列表中；Codex App 可能把该错误显示成通用的高负载 / 重连提示
  - 处理：先请求 `/v1/models` 查看可用模型，把 CC Switch / Codex Provider 的 `model` 改成 `codex-default` 或列表内已授权别名；不要直接沿用另一个 Provider 的 `gpt-5.5` 等模型名

- `403 access_policy_input_token_limit_exceeded`
  - 含义：请求输入估算 Token 超出该成员单请求输入上限
  - 处理：减少上下文 / 工具 schema，或在成员策略中调高“单请求输入 Token”

- `403 access_policy_output_token_limit_exceeded`
  - 含义：请求 `max_tokens` 超出该成员单请求输出上限
  - 处理：降低客户端 `max_tokens`，或在成员策略中调高“单请求输出 Token”；若客户端不传 `max_tokens`，网关会自动压到成员输出上限

- `413 request_tools_limit_exceeded`
  - 含义：公网成员请求携带的工具定义数量超过网关公网安全阀
  - 处理：减少一次请求中的工具数量；其他 `request_*_limit_exceeded` 同理表示公网请求 payload 过大或结构过重

- `429 session_safety_concurrency_exceeded`
  - 含义：同一上游账号当前进行中的请求数达到账号级并发安全阀
  - 处理：等待 `Retry-After` 后重试，或让公网成员路由到其他可用 `public-ready` 号池账号

- `429 session_safety_rate_limit_exceeded`
  - 含义：同一上游账号近 60 秒准入次数达到账号级短窗口安全阀
  - 处理：等待 60 秒窗口恢复，或扩充 / 调整 `public-ready` 号池账号；该限制会跨多把公网成员 Key 生效

- `503 gateway_api_key_not_configured`
  - 含义：网关已切到 API Key 模式，但本地尚未保存有效密钥
  - 处理：在桌面端先保存有效密钥，再重试

- `404 Route POST:/v1/responses not found`
  - 含义：运行中的安装版仍是旧版本，或请求没有进入当前网关服务
  - 处理：确认已安装包含 Responses 兼容入口的新版本，并重启 `com.local-ai-gateway.gateway` 常驻服务；若只在 CC Switch “获取模型列表”失败，同时检查是否被客户端拼成了 `/v1/v1/models`

- `400 Invalid 'input[n].call_id': string too long`
  - 含义：继续跨 Provider 旧会话时，历史工具调用 ID 超过官方 Responses API 的 64 字符上限；常见于一个 Provider 写入私有工具调用 ID，另一个 Provider 回放历史
  - 处理：当前本网关已对自身出入口和上游回放路径做短 ID 归一；若错误发生在切回 Cockpit Tools 后的旧会话，通常需要 Cockpit 侧同步处理，或新建会话继续

## 7. 快速连通性自检（可选）

在终端执行：

```bash
curl http://127.0.0.1:8787/v1/models
```

若启用 API Key 鉴权：

```bash
curl -H "Authorization: Bearer <你的 Local AI Gateway API Key>" \
  http://127.0.0.1:8787/v1/models
```

返回 `200` 且包含模型列表，表示基础链路已通。

公网入口未带 Key 的预期结果是 `401 gateway_api_key_required`。如果返回 `404`，优先检查 Cloudflare Public Hostname、Path `^/v1` 和 `cloudflared` connector 状态；如果返回 `401`，说明公网请求已经到达网关鉴权层。

## 8. 策略路由与路由预演示例

对于你当前“OpenClaw 持续接入本地网关”的用法，最常见的策略路由模板是：

- 目标：凡是来自 `OpenClaw` 的请求，都固定走某个指定 Codex 账号
- 匹配条件：
  - `clientTag = openclaw`
- 目标：
  - `modelAlias = codex-default`
  - `sessionId = <你想分配给 OpenClaw 的账号 ID>`

对应到桌面端左侧“策略路由”页：

- 规则名称：`OpenClaw 固定账号`
- 优先级：`10`
- 按客户端标签匹配：`openclaw`
- 按请求模型别名匹配：留空
- 目标模型别名：`codex-default`
- 目标会话标识：填目标账号的 `sessionId`、`profileId` 或 `accountId` 均可；若能唯一定位，本地网关会自动解析到真实会话

路由预演建议这样填：

- 客户端标签：`openclaw`
- 请求模型别名：`codex-default`
- 当前模型别名：`codex-default`
- 当前会话 ID：留空

预演结果如果显示：

- 命中规则：`OpenClaw 固定账号`
- 解析模型：`codex-default`
- 解析会话：`<你指定的会话 ID>`

就说明这条规则会在真实请求链路中生效。
