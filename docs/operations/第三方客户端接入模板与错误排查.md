# 第三方客户端接入模板与错误排查

> 2026.03.27

本文档用于统一 `OpenClaw`、`localRagHub` 等第三方客户端接入本地网关时的最小配置模板与错误排查方式。

你也可以直接在桌面端 `总览 -> 第三方接入模板` 中点击“复制”按钮获取对应模板（OpenClaw / localRagHub / 通用 cURL）。

## 1. 接入前检查

- 本地网关已启动
- 已选择可用的活动账号
- 已确认模型别名（默认 `codex-default`）
- 若启用了 API Key 鉴权：已在桌面端系统配置中保存有效密钥

## 2. 鉴权模式说明

- `none`：不校验第三方请求密钥，适合本机单用户调试
- `api-key`：第三方请求必须携带密钥，适合多应用共享本地网关

启用位置：桌面端 `诊断与系统` -> `第三方客户端接入鉴权`

补充说明：

- `clientTag` 建议显式填写，便于在账号卡片看到来源分布
- 网关优先从请求头读取 `x-local-ai-client-tag / x-client-tag / x-source-app`
- 若接入方未显式传 `clientTag`，网关会尝试从 `User-Agent` 推断常见客户端（如 `localraghub`、`openclaw`）

## 3. OpenClaw 接入模板

```ini
provider=openai
baseUrl=http://127.0.0.1:8787/v1
model=codex-default
clientTag=openclaw
# 若启用 API Key 鉴权，请加上：
# apiKey=<你的 Local AI Gateway API Key>
```

### 3.1 OpenClaw 真实配置写法

如果希望账号卡片里的“来源分布 Tag”稳定显示为 `openclaw`，推荐在 OpenClaw 的 provider 上显式写静态请求头，而不是只依赖 `User-Agent` 推断。

OpenClaw 官方配置参考已支持：

- `models.providers.<provider>.headers`

可直接写进 `~/.openclaw/openclaw.json` 的对应 provider：

```json
{
  "models": {
    "providers": {
      "openai": {
        "baseUrl": "http://127.0.0.1:8787/v1",
        "apiKey": "dummy",
        "api": "openai-completions",
        "headers": {
          "x-client-tag": "openclaw"
        }
      }
    }
  }
}
```

补充说明：

- 如果本地网关启用了 `api-key` 鉴权，OpenClaw 里的 `apiKey` 需要改成真实的网关 API Key，不能继续用 `dummy`
- `clientTag` 是本地网关用来识别“请求来自哪个第三方客户端”的标签，不会影响 OpenClaw 的正常模型调用
- 本项目网关会优先读取 `x-local-ai-client-tag / x-client-tag / x-source-app`，因此这里推荐写 `x-client-tag`

## 4. localRagHub 接入模板

```ini
provider=openai-compatible
baseUrl=http://127.0.0.1:8787/v1
model=codex-default
clientTag=localraghub
# 若启用 API Key 鉴权，请加上：
# apiKey=<你的 Local AI Gateway API Key>
```

## 5. 错误码速查

- `401 gateway_api_key_required`
  - 含义：当前网关启用了 API Key 鉴权，但请求未携带密钥
  - 处理：在第三方客户端补齐 `Authorization: Bearer <key>` 或 `x-api-key`

- `403 gateway_api_key_invalid`
  - 含义：请求携带了密钥，但与网关配置不一致
  - 处理：核对桌面端保存的密钥与第三方客户端配置是否一致

- `503 gateway_api_key_not_configured`
  - 含义：网关已切到 API Key 模式，但本地尚未保存有效密钥
  - 处理：在桌面端先保存有效密钥，再重试

## 6. 快速连通性自检（可选）

在终端执行：

```bash
curl http://127.0.0.1:8787/v1/models
```

若启用 API Key 鉴权：

```bash
curl -H "Authorization: Bearer <你的 Local AI Gateway API Key>" \
  http://127.0.0.1:8787/v1/models
```

返回 `200` 且包含模型列表，表示基础链路已通。

## 7. 策略路由与路由预演示例

对于你当前“OpenClaw 持续接入本地网关”的用法，最常见的策略路由模板是：

- 目标：凡是来自 `OpenClaw` 的请求，都固定走某个指定 Codex 账号
- 匹配条件：
  - `clientTag = openclaw`
- 目标：
  - `modelAlias = codex-default`
  - `sessionId = <你想分配给 OpenClaw 的账号 ID>`

对应到桌面端“Provider 服务配置 -> 策略路由（第二期）”：

- 规则名称：`OpenClaw 固定账号`
- 优先级：`10`
- 按客户端标签匹配：`openclaw`
- 按请求模型别名匹配：留空
- 目标模型别名：`codex-default`
- 目标会话标识：填目标账号的 `sessionId`、`profileId` 或 `accountId` 均可；若能唯一定位，本地网关会自动解析到真实会话

路由预演建议这样填：

- 客户端标签：`openclaw`
- 请求模型别名：`codex-default`
- 当前模型别名：`codex-default`
- 当前会话 ID：留空

预演结果如果显示：

- 命中规则：`OpenClaw 固定账号`
- 解析模型：`codex-default`
- 解析会话：`<你指定的会话 ID>`

就说明这条规则会在真实请求链路中生效。
