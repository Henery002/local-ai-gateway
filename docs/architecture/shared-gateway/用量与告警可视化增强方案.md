# 用量与告警可视化增强方案

更新时间：2026-05-25

## 背景

当前“用量与告警”模块已经具备成员、Access Key、模型、号池和告警事件的真实数据底座，但图表层仍主要由原生 DOM、CSS 和少量手写 SVG 拼接完成。该实现适合早期闭环验证，却不适合继续承载运营看板级的缩放、平移、多序列 tooltip、图例联动和复杂图表组合。

Electron 控制台本质运行在 Chromium 渲染层，能力并不弱于普通 Web 页面。限制主要来自当前没有专业图表引擎，也没有独立的 chart lifecycle 管理，而不是 Electron 架构本身。

## 选型结论

优先在现有 Electron 控制台中引入 Apache ECharts，不切换为独立 Web 端，也不重写现有桌面端架构。

原因：

- ECharts 覆盖折线图、面积图、柱状图、饼图、堆叠图、tooltip、legend、dataZoom 等运营看板高频能力。
- 当前项目没有 Vite / Webpack 等前端 bundler，ECharts 可以通过 UMD 文件在渲染层运行时加载，避免一次性引入大规模构建链变更。
- 继续复用现有本地 SQLite 中的 `inference_usage_events`、`access_alert_events`、成员 / Key / Policy 配置，不重置、不删除历史业务数据。
- 后续如果需要服务端版或 Web 控制台，ECharts 图表配置和 `/admin/usage/analytics` 数据接口仍可复用。

## 切片计划

### 切片 1：ECharts 接入与核心图表升级

目标：在不改变数据写入、不新增破坏性迁移的前提下，把第一屏核心图表升级为专业图表渲染。

范围：

- 引入 ECharts 运行时依赖。
- 新增桌面端图表生命周期管理：初始化、更新、resize、dispose。
- 将“Token 消耗走势”升级为横向拉满折线 / 面积图，展示近 24 小时总体 Token 趋势。
- 将“Token 构成”升级为 donut 图，展示输入、输出、缓存、思考 Token 占比。
- 将“成员观测排行”升级为横向柱状图，并继续沿用当前时间窗口口径。
- 增加成员筛选入口，第一段先基于现有 `usageSummary` 做成员维度过滤；更细模型 / 号池按成员过滤由切片 2 的 analytics API 补齐。

### 切片 2：用量分析 API

目标：把现有摘要接口升级为更适合图表消费的分析接口。

建议新增：

- `GET /admin/usage/analytics`
- 支持 `range=24h|7d|30d|all|custom`
- 支持 `granularity=hour|day|week|month|auto`
- 支持 `consumerId / accessKeyId / modelAlias / poolId / outcome` 筛选
- 返回统一 timeline、token mix、ranking、outcome、latency、member health 基础字段

该接口只读取现有 SQLite 业务数据，不清理历史，不改变 AccessPolicy 执行逻辑。

### 切片 3：成员访问健康度

目标：把管理员最关心的“某个成员近期是否健康”提级为横向大卡片。

成员健康度建议维度：

- 成功率与失败率
- 失败错误类型：上游限流、网关错误、额度告警、Key 异常、号池拒绝
- 平均延迟与近期波动
- Token 消耗与额度余量
- 最近上线 / 最近请求时间

第一版健康分建议：

- 成功率：40%
- 失败率与错误严重度：25%
- 延迟表现：15%
- 额度 / 到期风险：10%
- 近期活跃稳定性：10%

### 切片 4：真实数据态与视觉精修

目标：基于实际公网试运行数据继续打磨交互。

范围：

- tooltip 文案、空态、缩放范围、移动窗口适配。
- 大数据量下的 timeline 性能验证。
- 成员矩阵、告警联动和请求审计跳转。
- 根据真实使用习惯调整默认筛选和默认时间范围。

## 持久化与安全边界

- 图表库只改变展示层，不改变 `inference_usage_events`、`access_alert_events`、成员、Key、Policy、账号资产、号池配置的存储语义。
- 不新增“清空历史数据”动作。
- 不展示完整 API Key、OAuth token 或上游账号敏感信息。
- 成员筛选和图表交互只影响管理员本地观测视角，不影响公网成员请求、号池调度或 AccessPolicy 执行。
