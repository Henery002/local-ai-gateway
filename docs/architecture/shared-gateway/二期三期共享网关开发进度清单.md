> 2026-05-23 18:55 CST

### 1.0.0-I 跨 Provider 存量会话连续性保护

> 2026-05-23 15:10 CST

本轮定位 Codex App 在 CC Switch 切换 Cockpit Tools 与 Local AI Gateway 公网 Provider 后，继续另一侧既有会话时报 `Invalid 'input[4].call_id': string too long` 的根因与可修边界：

- 根因判断：Codex 会话历史会保存工具调用 ID；不同 Provider 可能写入不同格式的 `call_id / tool_call_id / response item id`。当另一 Provider 回放这段历史到官方 Responses API 时，官方上游要求 `input[].call_id` 最长 64 字符，超长 ID 会被直接拒绝。
- 已修复本网关侧：OpenAI-compatible 层在 Responses -> Chat、Chat -> Responses、Responses SSE 输出时都会把超长工具调用 ID 稳定归一为 64 字符内短 ID；Codex provider 向官方 `/codex/responses` 回放历史工具调用时也会归一，并保持 `function_call` 与 `function_call_output` 的 `call_id` 对齐。
- 已降低未来污染：Codex provider 不再把官方 Responses SSE 的 `call_id|item_id` 复合串作为对外工具调用 ID 写回客户端，避免本网关生成新的超长历史 ID。
- 能力边界：新会话、以及未来经本网关生成 / 回放的会话会更可迁移；但已经由其他 Provider 写入 Codex 本地会话历史的私有超长 ID，切回该 Provider 时是否能继续，取决于该 Provider 是否也做同类归一。本网关不能直接修改 Cockpit 发往官方上游的请求。
- 不做自动历史迁移：本轮不改写 `~/.codex` 会话文件，不批量清洗历史 transcript，避免破坏用户存量会话、项目数据和回滚能力。
