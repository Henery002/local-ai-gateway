# 二期 / 三期共享网关开发进度清单

> 2026.05.16

本文档用于跟踪 `Local AI Gateway` 共享网关二期 / 三期重构的实际开发节奏。技术目标以《二期 / 三期共享网关重构技术方案》为准，UI/UX 输入以本机「figma UI/UX重构方案」为设计基线。

## 1. 当前结论

- 当前开发分支：`codex/shared-gateway-next`。
- 当前工作阶段：`P1-B AccessConsumer / AccessKey / AccessPolicy` 已完成后端内核、成员创建和成员详情 / key 状态管理第一版；下一步补额度 / QPS / 并发限制和 P1-C 号池授权。
- 当前不做：公网真实开放、公开注册、计费、多租户运营、Cockpit / OpenClaw 原始配置写入。
- 当前优先级：先把桌面端 UI/UX、访问成员模型和共享网关安全边界对齐，再恢复 AccessPolicy、号池授权和用量告警功能开发。

## 3. 需要手动确认的点

以下问题会影响首个 UI 代码切片，进入对应实现前需要用户确认：

1. 主题策略：是否将 Figma 深色主题作为二期共享网关默认主题。
   - 推荐：二期新 UI 默认深色主题，同时用 token 层保留后续浅色 / 跟随系统主题扩展口子。
2. 开发顺序：P0 是否先做视觉骨架，再并行补 LAN 后端能力。
   - 推荐：先做 Dashboard / Access & Keys / Accounts 的视觉骨架和状态映射，再接入真实 AccessConsumer / AccessKey / AccessPolicy。
3. 图表方案：是否第一版避免引入 Chart.js。
   - 推荐：P0 先用轻量 SVG / CSS 图表容器并接真实数据结构，等 Usage 页面进入 P1/P2 后再决定是否引入图表库。
4. LAN 入口：二期第一版是否优先内置 LAN listener。
   - 推荐：优先内置 LAN listener，同时保留 Tailscale / ZeroTier / 反代说明作为部署建议，不把它们作为第一版依赖。
