# 公网用户自助用量额度查询页技术方案

> 更新时间：2026-05-27
> 状态：MVP 实施中

## 目标与边界

本方案为公网共享中转站补充一个前期简易的用户自助查询入口，让成员通过公网链接打开页面，输入自己的 RelayGate API Key 后，仅查看自己账户下的成员信息、Key 脱敏信息、额度、用量、趋势和模型消耗。

MVP 不引入云服务器，不新建独立后端，不暴露管理员控制台。页面和只读接口复用当前本机网关、现有 Cloudflare Tunnel 与 `https://gateway.henery.top/v1` 公网入口。

明确不做：

- 不开放 `/admin/*` 到公网。
- 不展示完整 API Key、OAuth token、上游账号邮箱、prompt 正文或原始响应体。
- 不允许用户通过查询参数指定任意 `consumerId` / `accessKeyId` 查看他人数据。
- 不提供修改成员、Key、策略、号池、账号资产的能力。
- 不改变现有计费、额度扣减、路由或账号池调度逻辑。

## 路由设计

公网入口继续限定在 `/v1/*` 下，适配当前 Cloudflare Tunnel Path `^/v1`。

| 路由 | 鉴权 | 用途 |
| --- | --- | --- |
| `GET /v1/account` | 无需 Key | 返回自助查询静态页面。页面本身不含敏感数据。 |
| `GET /v1/user/profile` | 用户 API Key | 返回当前 Key 对应的成员、Key 脱敏元数据、策略摘要和额度摘要。 |
| `GET /v1/user/usage/summary?range=24h\|7d\|30d\|all` | 用户 API Key | 返回当前成员 + 当前 Key 范围内的用量汇总、趋势和排行。 |
| `GET /v1/user/balance` | 用户 API Key | 保留现有兼容余额接口，供 CC Switch / Codex 兼容查询继续使用。 |

## 鉴权与安全边界

用户自助接口复用现有推理 API Key 鉴权链路：

1. 页面不会把 Key 放入 URL，不使用 query string 传递 Key。
2. 前端请求使用 `Authorization: Bearer <api_key>`。
3. 服务端通过现有 `resolveAuthAndClientTag()` 解析 Access Key、成员和策略。
4. 只有解析出 `accessContext` 的成员 Key 能访问自助接口；普通全局网关 Key 或客户端映射 Key 不返回成员画像。
5. 服务端始终以鉴权上下文里的 `consumerId` 和 `accessKeyId` 作为过滤条件，忽略任何用户伪造的成员 / Key 查询参数。
6. 返回内容只包含脱敏元数据：Key prefix/suffix、Key 名称、状态、到期时间、成员名称、类型、状态、策略限制、模型和号池授权。
7. 错误响应沿用现有 `GatewayError` 结构，缺失、无效、暂停、过期 Key 返回 401/403，不泄露 Key 是否存在之外的敏感细节。
8. MVP CORS 保持同源，不额外放宽跨域；公网页面和接口同源部署在 `gateway.henery.top`。

后续商业化增强建议单独切片：

- 增加自助接口 per-key 轻量限流。
- 增加短期 session token，避免每次请求都传用户原始 Key。
- 增加验证码或一次性查询口令，降低公网撞库和脚本探测噪音。
- 将公网自助页独立到更好记的路径或子域，但仍反代到 `/v1` 范围内。

## 数据口径

### profile 响应摘要

```json
{
  "ok": true,
  "data": {
    "consumer": {
      "id": "consumer-public",
      "name": "Public User",
      "type": "public-user",
      "status": "enabled",
      "clientTag": "public-user"
    },
    "accessKey": {
      "id": "key-public",
      "name": "Public Key",
      "keyPrefix": "lag_alic",
      "keySuffix": "3456",
      "status": "enabled"
    },
    "policy": {
      "allowedModelAliases": ["codex-5.5"],
      "allowedPoolIds": ["public-ready"],
      "quota": {
        "periodDays": 30,
        "periodTokenLimit": 1000000
      },
      "limits": {
        "requestsPerMinute": 60,
        "maxConcurrentRequests": 2
      }
    },
    "balance": {
      "unit": "tokens",
      "quotaMode": "period",
      "total": 1000000,
      "used": 120000,
      "remaining": 880000,
      "resetAt": 1780000000000
    }
  }
}
```

### usage 响应摘要

`/v1/user/usage/summary` 复用当前本地 SQLite `inference_usage_events` 聚合能力，但强制加上当前用户的 `consumerId` 和 `accessKeyId`。

返回内容包含：

- `summary.totals`：请求、成功、失败、延迟、输入 / 输出 / 缓存 / 思考 / 总 Token。
- `summary.modelTimeline`：按小时或天聚合的模型趋势。
- `summary.models`：当前用户模型消耗排行。
- `summary.accessKeys`：当前 Key 维度聚合，MVP 只会显示当前 Key。
- `range` / `granularity` / `filters`：用于前端解释当前窗口和过滤范围。

## UI 设计

公网自助页参照桌面端“用量与告警”模块的观测形式，但保持更轻量；视觉层复用桌面控制台的中性色 / 品牌蓝 token、白底运营卡片、细边框、轻阴影、语义色和小卡片观测语言，不再使用独立的营销落地页风格。

- 左侧：RelayGate Account Center 品牌区、成员 Key 输入、观测窗口、查询 / 刷新按钮、安全边界说明。
- 顶部：Public User Console 摘要区，说明当前页面只属于 `/v1/*` 公网查询面。
- KPI 卡片：剩余额度、已用 Token、请求数、成功率。
- 额度观测：成员名、Key 前后缀、额度模式、Key 状态、允许模型、输入 / 输出 / 缓存 / 思考统计和剩余比例。
- Token 构成：输入、输出、缓存、思考四段横向占比条。
- 趋势图：近 24h 用小时柱，近 7d / 30d 用天柱；MVP 不额外引入 CDN 或新前端构建链，使用轻量 DOM/CSS 渲染。
- 模型排行：展示模型别名、Token 和请求数。
- 安全提示：页面底部明确“仅本次浏览器会话使用 Key，不会显示完整 Key，不会读取 prompt 正文”。

页面优先保证移动端可用：单列卡片、按钮可点击、Key 输入框支持密码显示 / 隐藏切换。

## 验收标准

- 公网可打开 `https://gateway.henery.top/v1/account`。
- 未输入 Key 时只能看到页面，不能获取任何个人数据。
- 输入有效成员 Key 后，可以看到本人额度、用量、趋势和模型排行。
- 输入无效、暂停、过期 Key 时提示鉴权失败，不泄露敏感字段。
- 自助接口响应不包含完整 API Key、`keyHash`、上游账号邮箱、OAuth token 或 prompt 正文。
- `/admin/*` 仍只允许本机管理员访问，公网 Tunnel 仍只暴露 `/v1/*`。
