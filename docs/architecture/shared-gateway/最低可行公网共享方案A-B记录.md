# 最低可行公网共享方案 A / B 记录

> 2026-05-19

本文记录后续“极小范围公网共享”的两个最低可行方案。当前只做方案沉淀，不代表已经实施、部署或开放公网入口。

## 1. 适用目标

目标不是公网商业化平台，而是：

- 只邀请极少数可信成员；
- 仍以当前 Mac 上运行的 `Local AI Gateway` 作为服务端；
- 只有本机开机、网关运行、网络连通时才可用；
- 对外只暴露 OpenAI-compatible 推理面，管理面仍保持本机可用；
- 必须继续使用成员 API Key、限额、号池授权和用量观测做边界控制。

## 2. 方案 A：Cloudflare Tunnel

### 形态

在本机运行 `cloudflared tunnel`，把一个受控域名转发到本机网关推理端，例如：

```text
https://gateway.example.com/v1 -> http://127.0.0.1:8787/v1
```

### 需要准备

- 一个可托管到 Cloudflare 的域名；
- Cloudflare 账号；
- 本机安装并登录 `cloudflared`；
- `Local AI Gateway` 已启用 API Key 鉴权，并为外部成员创建独立成员 Key；
- macOS 睡眠策略、电源和网络稳定性需要手动保障。

### 成本

- Cloudflare Tunnel 基础能力通常可零成本起步；
- 域名按年付费，取决于域名后缀；
- 主要代价是本机持续开机、网络上传、故障自维护，以及对 Cloudflare 账号和域名的依赖。

### 优点

- 不需要家庭宽带公网 IP 和路由器端口映射；
- 自动获得 HTTPS；
- 链路对被邀请成员最接近普通公网服务，只需要 `base_url + api_key`；
- 后续可继续叠加 Access、WAF、域名迁移或独立 server edition。

### 风险与限制

- 本机离线、睡眠、换网或 `cloudflared` 退出都会导致外部不可用；
- 如果误把管理面暴露到公网，风险很高；
- 免费形态不等同于商业 SLA；
- 仍需在网关侧强制成员级限额、过期、模型和号池边界。

## 3. 方案 B：Tailscale Funnel

### 形态

通过 Tailscale Funnel 把本机服务暴露为 HTTPS 地址，外部成员通过该地址访问当前网关推理面。

### 需要准备

- Tailscale 账号；
- 本机安装并登录 Tailscale；
- 开启并配置 Funnel；
- `Local AI Gateway` 已启用 API Key 鉴权，并为外部成员创建独立成员 Key。

### 成本

- 小规模个人 / 团队试用通常可以低成本甚至零成本起步；
- 不需要单独域名也能拿到可访问入口；
- 主要代价仍是本机开机、网络稳定和 Tailscale 账号侧配置维护。

### 优点

- 上手快，适合验证“本机开机即服务”的最低可行公网访问；
- 不要求路由器端口映射；
- 对极少数可信成员邀请制试用足够轻量。

### 风险与限制

- Funnel 可用性、流量策略和账号套餐能力可能随 Tailscale 规则变化，需要实施前复核；
- 对外地址、访问策略和组织配置不如正式反代 / server edition 可控；
- 仍不能绕过网关侧 API Key、成员限额、号池隔离和管理面隔离。

## 4. 推荐顺序

如果只是邀请 1-2 个可信成员做公网试用，推荐顺序是：

1. 优先方案 A：Cloudflare Tunnel + 独立成员 Key + 严格限额。
2. 若暂时不想处理域名，使用方案 B：Tailscale Funnel 做短期验证。
3. 一旦进入更稳定或更大范围共享，迁移到独立 `server edition` / `public gateway`，不要直接把桌面管理端作为公网产品长期外放。

## 5. 与当前二期实现的关系

当前二期应继续把重点放在：

- `/v1/*` 推理面可被共享成员使用；
- `/admin/*` 管理面只允许本机访问；
- 成员 Key、AccessPolicy、号池授权、Token 统计和告警在本机闭环；
- 所有外部导入账号继续保持只读边界，不主动刷新 Cockpit / OpenClaw 的 refresh token。

方案 A / B 只是公网入口层。它们不能替代网关内的成员身份、额度、限流、风控和观测能力。
